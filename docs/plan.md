# 軽量画像編集アプリ 開発仕様書（初期案）

## 1. 概要

Windows 11のSnipping Toolの手軽さと、Photoshopの基本的な画像編集機能を組み合わせた、軽量な画像編集アプリケーションを開発する。

Windows標準のスクリーンショット機能を利用することで、キャプチャ処理自体は実装せず、**キャプチャした画像を素早く編集・加工・出力すること**に特化する。

### 開発コンセプト

- Snipping Toolのような手軽さと高速起動
- Photoshopのようなレイヤー編集
- シングルウィンドウによるシンプルなUX
- 複数画像をタブで管理
- クリップボードとの連携を重視
- 機能を必要以上に増やさず、直感的に操作できるUI

## 2. 技術構成

| 項目 | 採用技術 |
|---|---|
| 対応OS | Windows 11 |
| 開発環境 | Visual Studio 2026 |
| 開発言語 | C# |
| フレームワーク | .NET 10 |
| UIフレームワーク | WPF |
| 描画エンジン | SkiaSharp |
| アーキテクチャ | Document / Layer / Renderer分離 |
| UI更新方式 | イベント駆動 + 必要に応じたPull型更新 |
| 配布 | Windows x64 |

### 技術選定の理由

**WPF**
- C#による高い開発効率
- AIを使ったバイブコーディングとの相性
- XAMLによる柔軟なUI設計
- タブ、ツールバー、パネル等の実装が容易
- Windows専用アプリとして成熟した技術基盤

**SkiaSharp**
- C++製2D描画エンジンSkiaの.NETバインディング
- 画像の拡大縮小、回転、合成
- テキスト、図形、アンチエイリアス描画
- 透明度やクリッピングへの対応
- 画像出力処理への利用

**起動速度**
- WPFはNative AOT非対応
- ReadyToRunによる起動速度改善を検討
- 不要な初期化処理を遅延実行
- 初回起動と2回目以降の起動時間を測定
- アプリ起動中は新規プロセスを生成せず、タブ追加で対応

## 3. アプリケーションの基本動作

### 3.1 スクリーンショットの取得

画面キャプチャにはWindows 11標準機能を使用する。

1. `Win + Shift + S` でスクリーンショットを取得
2. Windowsが画像をクリップボードへ格納
3. 自作画像エディタを起動
4. クリップボード画像を自動取得
5. 新規Documentとして画像を表示

独自のCapture Agentや画面キャプチャ機能は実装しない。

### 3.2 アプリ起動時

**クリップボードに画像がある場合**
- 画像の幅・高さを取得
- 同サイズの新規Documentを作成
- クリップボード画像をImageLayerとして追加
- 編集画面に表示

**クリップボードに画像がない場合**
- 空の編集画面を表示
- 新規画像作成、ファイルを開く等の操作を受け付ける

クリップボード取得に失敗してもアプリの起動を妨げない。

### 3.3 シングルインスタンス動作

- アプリケーションは原則として単一プロセス
- 起動済みの場合は既存ウィンドウをアクティブ化
- 新しいクリップボード画像がある場合は、新規タブとして追加
- 同一画像の重複取り込み防止は今後検討

## 4. 新規画像作成

### 4.1 初期サイズ

新規画像作成ダイアログでは、**クリップボード画像の幅・高さを自動的に初期値として使用する。**

「クリップボード画像のサイズを使用」ボタンは設けない。

| 条件 | 初期サイズ |
|---|---|
| クリップボードに画像あり | 画像の幅・高さ |
| クリップボードに画像なし | 前回作成した画像サイズ |
| 初回起動・履歴なし | 1920×1080（暫定） |

幅と高さはユーザーが自由に変更できる。

### 4.2 背景色

- 透明
- 白
- 黒

初期値は透明とする。

### 4.3 新規作成と貼り付けの違い

**新規画像作成**
- クリップボードから画像サイズだけを参照
- 画像そのものは貼り付けない
- 指定したサイズ・背景で新規Documentを作成

**クリップボード貼り付け**
- 画像データを取得
- ImageLayerとしてDocumentに追加

## 5. 画像編集機能

### 5.1 レイヤー

以下の種類をサポートする。

| レイヤー | 概要 |
|---|---|
| ImageLayer | ラスタ画像 |
| TextLayer | 編集可能なテキスト |
| ShapeLayer | 矩形、円、矢印など |

基本操作：
- 図形は矩形・円・矢印・線。線の種類（実線・破線・点線）と、矩形の角の丸み
- レイヤー追加・削除
- レイヤーの並べ替え
- 表示・非表示切り替え
- 不透明度変更
- レイヤー移動
- レイヤーのラスタライズ
- レイヤーの複製
- 下のレイヤーとの結合（どちらも表示中のレイヤーのみ）
- 空のレイヤーの追加（キャンバスと同じ大きさの透明な画像レイヤー）
- 一覧でのドラッグ並べ替え
- 一覧にサムネイルを表示（見た目が変わったときだけ更新）

### 5.2 テキスト

- テキスト追加
- 文字サイズ変更
- フォント変更
- 文字色変更
- テキスト位置変更
- 太字・斜体
- 影（チェックで ON/OFF。濃さ・ぼかしはスライダー、ずれは数値）と縁取り（太さ・色）
- テキスト内容の再編集
- TextLayerからImageLayerへのラスタライズ
- キャンバス上でテキストをダブルクリックして直接編集（Escape または Ctrl + Enter で終了）

### 5.3 キャンバス操作

- ズームイン・ズームアウト
- パン操作
- キャンバスサイズ変更
- 画像サイズ変更（再サンプリング）
- DPIなど解像度メタデータの変更（必要性を検討）
- 範囲選択（矩形。ドラッグで作成、ハンドルで変形、移動、Esc で解除）
- 画像の切り抜き（選択範囲の大きさにキャンバスを変更し、画像レイヤーも範囲内だけに切り詰める。テキスト・図形は編集可能なまま位置だけ移動。表示倍率は変えない）
- 選択範囲のコピー（選択レイヤーの範囲内のピクセル）・切り取り（選択中の画像レイヤーの範囲を透明にしてコピー）

### 5.4 キャンバス上の直接操作

- クリックでレイヤーを選択し、ドラッグで移動する（画像の透明部分と、枠線だけの図形の内側はクリックが下のレイヤーに通る）
- 選択中の図形にはハンドルを表示し、ドラッグで大きさを変える（矩形・楕円は 8 点、矢印は始点と終点）
- テキストはダブルクリックでその場で編集する
- 矢印キーで選択レイヤーを 1px ずつ、Shift を併用して 10px ずつ動かす
- Delete キーで選択レイヤーを削除する
- いずれも Undo / Redo の対象とし、連続した操作（ドラッグ、文字入力、キー押しっぱなし）は 1 回分にまとめる

### 5.5 編集履歴

- Undo / Redo
- 操作コマンドを履歴として保持
- ラスタ画像の変更には必要に応じて差分データを利用
- 画像全体の無駄な複製を回避

## 6. 画像の入出力

### 6.1 入力

- クリップボード画像
- PNG
- JPEG
- WebP
- BMP（対応を検討）
- ドラッグ＆ドロップ

### 6.2 出力

- PNG
- JPEG
- WebP
- BMP（対応を検討）
- 編集結果をクリップボードへコピー

### 6.3 プロジェクト保存

画像出力とは別に、レイヤー情報を保持する独自プロジェクト形式を用意する。

保存対象：
- キャンバスサイズ
- レイヤー構成
- レイヤー順序
- 画像データ
- テキスト情報
- 図形情報
- 各種レイヤープロパティ

**ファイル形式（決定）**
- 拡張子は `.trimx`。
- 中身は ZIP コンテナ。`project.json`（キャンバスサイズ、レイヤー順序・プロパティ）と、画像レイヤーごとのロスレス PNG（`images/N.png`）を格納する。
- テキスト・図形はプロパティのみを保存するため、読み込み後も編集できる。
- `project.json` には形式バージョン（現在 1）を持たせ、新しいバージョンのファイルは読み込まずに通知する。
- 保存は一時ファイルへ書いてから置き換えるため、保存に失敗しても既存ファイルは壊れない。

**保存と書き出しの違い**
- `Ctrl + S` / `Ctrl + Shift + S` はプロジェクト（`.trimx`）の保存。
- 画像としての出力は「書き出し」（`Ctrl + E`）。PNG / JPEG / WebP を選べる。JPEG は透明部分を白で塗りつぶす。WebP はロスレス。BMP の出力は見送り。
- 「ファイルを開く」はプロジェクトと画像（PNG / JPEG / WebP / BMP）の両方を受け付け、ドラッグ＆ドロップでも開ける。

## 7. UI / UX

### 7.1 基本方針

- シングルウィンドウ
- 複数タブ対応
- ダークテーマを基本とする
- ツールバーはアイコンだけで構成し、名前と説明は ToolTip で伝える。左 = ファイル（新規・開く・保存・書き出し）、中央 = 描く・編集（ペン・図形・テキスト | 切り取り・範囲選択・切り抜き | キャンバス・画像サイズ | フィット | 元に戻す・やり直し）、右 = 貼り付け・コピー の 3 つに寄せ、グループの間は縦線で区切る
- レイヤー一覧の表示切替は目のアイコン。一覧の右クリックメニューに「画像レイヤーにラスタライズ」（できるレイヤーのみ表示）と「下のレイヤーと結合」を置く
- レイヤーパネルを配置（操作ボタンは小さなアイコンだけを 1 行に並べ、名前は ToolTip で伝える。画面を占有しないため）
- 編集キャンバスを中心に配置
- 必要な機能だけを表示する
- 右側のパネルは、上にインスペクタ（選択中のテキスト・図形の詳細）、下にレイヤー一覧を置く。境目の分割バーをドラッグして高さを変えられ、選択レイヤーの種類によって自動では変わらない（レイヤー一覧の位置が動かないようにするため）。キャンバスと右パネルの境目も分割バーで、ドラッグして幅を変えられる。ウィンドウの高さが変わったときは、上下の割合を保つ（それぞれの最小の高さの範囲内）
- 図形の追加は、ツールバーの「図形」ボタンを押すと形の選択肢（矩形・楕円・矢印）が表示される方式（ボタンを並べない）
- ペン: ツールバーの「ペン」を押すと描画モードになり、同時にポップアップで色（パレット + 「その他の色…」のカラーピッカー。色空間の四角と色相バーから選べ、HSB・RGB・16 進の数値でも指定できる。Lab / CMYK は見送り）と太さを選べる。キャンバスをドラッグすると線が引かれる。描き先は Photoshop 方式で、表示中の画像レイヤーを選択していればそのレイヤーに直接描き、それ以外（テキスト・図形を選択中など）は透明な画像レイヤーを新しく作ってそこに描く（以後の線はそのレイヤーに続く）。1 本の線が Undo 1 回分。Esc で描画モードを終える（テキスト・図形を追加したときも自動で終える）。描画モード中のカーソルはペンの形。蛍光ペン・消しゴムは未対応
- マイカラー: カラーピッカーで決めた色を、新しい順に最大 4 色まで自動で記録して次回以降も使える（操作を増やさないため手動登録・削除は設けない）。アプリ共通のパレットとし、ペンのほかテキスト・図形の色欄の「…」ボタンからも同じカラーピッカーで選べる（選んだ色はマイカラーに入る）
- 設定: ツールバー右端の歯車から設定画面を開く。テーマ（システム / ダーク / ライト）、ツールバーのラベル表示の ON/OFF、コピーライト表示、「描画の設定をデフォルトに戻す」。変更は即時に反映し、`%LOCALAPPDATA%\Trimx\TrimxSetting.json` に保存する
- 新しいテキストの初期文字列は設定画面で変えられる（既定「テキスト」）
- 状態の記憶: アプリが勝手に覚えるもの（前回の新規画像サイズ、マイカラー、ペンの色と太さ、テキスト・図形の前回の見た目と図形の大きさ、右パネルの幅、インスペクターの高さ）は設定とは別に `%LOCALAPPDATA%\Trimx\TrimxState.json` へ保存する。新しくテキスト・図形・ペンを使うとき、前回の見た目を引き継ぐ。今後ウィンドウサイズなども状態として保存する予定
- 画面下にステータスバーを置き、左下に現在の表示倍率を表示する（100% = 画像 1px が画面 1px）。倍率をクリックするとプリセット（400% / 200% / 100% / 50% / 25% / 画面に合わせる）を選べる。直接の数値入力は見送り
- 未保存の確認: タブを閉じるとき・アプリ終了時に、保存（プロジェクト保存）も出力（画像の書き出し・クリップボードへのコピー）もしていない変更があれば確認する。出力した時点で「渡した」とみなし、その後に編集した分だけが対象になる（スクリーンショットを加工してコピーし、そのまま閉じる使い方で毎回確認が出ないようにするため）。タブ名の「●」が未保存を表す

## 12. 最終方針

本アプリはPhotoshopの代替を目指すものではなく、**Windowsのスクリーンショットから素早く画像を編集・加工し、保存・共有するための軽量画像エディタ**として開発する。

最も重視するのは次の3点。

1. **高速起動**：起動してすぐ編集を開始できる。
2. **直感的な操作**：不要な操作やダイアログを減らす。
3. **レイヤー編集**：テキストや図形を後から自由に編集できる。

WPFとSkiaSharpを採用し、バイブコーディングで段階的に機能を実装する。

# Implementation notes (behavior, class names, rationale per feature)

A reference for the details of each feature. You do not need to read it every time; consult it when touching the relevant feature. For the overview, design rules, and conventions, see `project.md`, `architecture.md`, and `conventions.md`. The primary source for requirements is `docs/plan.md` (Japanese).

The app UI is in Japanese. Quoted Japanese strings below are the actual UI labels.

## Status

- Branding: `assets/branding/trimx-banner.png` is the GitHub README banner. `trimx-icon.png` is the full-size rainbow layered-canvas mark on a navy square background. `trimx.ico` contains 16, 20, 24, 32, 40, 48, 64, 128, and 256 px 32-bit DIB frames, embedded in the executable via `ApplicationIcon` in `Trimx.csproj`. `trimx-icon-32.png` is a native-size preview. README placement is not applied yet.

- Phase 1 implemented: image display (centered in the viewport; scrollbars appear only in the direction where the image is larger than the viewport; no drag-to-pan), zoom (mouse wheel, around the cursor), clipboard image retrieval, loading at startup, Ctrl+0 to fit.
- Phase 2 implemented: multiple tabs (each tab keeps its own zoom, pan, and selected layer), ImageLayer / TextLayer / ShapeLayer (rectangle, ellipse, arrow), layer panel (select, toggle visibility, opacity, move up/down, delete), new-image dialog (Ctrl+N; initial size is clipboard image, then last size, then 1920×1080).
  - Ctrl+V: if a tab exists, add as an ImageLayer above the selected layer; otherwise open a new tab.
  - Text and shapes are added from the toolbar with default values (editing was implemented in Phase 3).
  - The last new-image size is saved in `%LOCALAPPDATA%\Trimx\TrimxState.json` (StateService).
- Two-project layout: `Trimx.Core` (net10.0, WPF-independent: `Documents` / `Rendering` / `Commands` / `Editing` (DocumentFactory, LayerFactory) / `Services`) and `Trimx` (WPF UI: MainWindow, CanvasView, DocumentTab, LayerPanel (LayerItem), PropertiesPanel, ColorField, NewImageDialog, ResizeDialog; Services: Clipboard, Settings, BitmapConverter).
- Phase 3 implemented (interactions not verified on a real screen): Undo / Redo (Ctrl+Z / Ctrl+Y, toolbar), selecting and drag-moving layers on the canvas, editing text and shapes, rasterize, canvas resize, image resize.
  - `Trimx.Core.Commands`: `IDocumentCommand` (Execute / Undo / Dispose), `CommandHistory` (per tab, up to 100 steps).
  - Continuous operations (sliders, typing, dragging) use `Execute(command, allowMerge: true)` to collapse into one step and call `EndMerge()` when the operation ends. One-off operations such as clicks do not pass allowMerge (otherwise they would be merged instead of becoming separate steps).
  - Commands: AddLayer / RemoveLayer / MoveLayer / ReplaceLayer / SetLayerPosition / SetLayerProperty (via the `LayerCommands` factory) / ResizeCanvas / ResizeImage.
  - Document changes must always go through `DocumentTab` (`Execute`, etc.) so they land in the history. Never modify Layer properties or the Document directly from the UI.
  - Layer ownership: a remove command owns the layer while applied, an add command owns it while undone, and a replace command owns the layer on the side not in use; the owner disposes it when the command leaves the history.
  - Selection and move: `LayerHitTester` (image layers ignore transparent pixels; the interior of a rectangle or ellipse that has only an outline is click-through). The selected layer is shown with a frame.
  - Properties panel (`PropertiesPanel`): text (content, font, size, color) and shapes (width, height, stroke width, stroke color, fill) update live while typing. The font list is loaded on first display (so startup stays fast). Colors use `ColorField` (#RRGGBB / #AARRGGBB plus presets). Rasterizing is `LayerRasterizer` (invoked from the layer list's context menu; there is no button in the inspector).
  - Canvas resize shifts existing layers according to an anchor position (3×3). Image resize resamples image layers; text and shapes stay editable and only their geometry is scaled. The history keeps the original bitmaps for Undo.
  - A text layer's name follows the first line of its content unless it has been renamed. Always change the name after changing the text (otherwise the edit box that receives the change notification is overwritten with stale text, the caret jumps to the start, and typing comes out reversed).
- Phase 3 additional polish (layers and UX; verified on a real screen only for button operations and confirmation dialogs; mouse and keyboard interactions not verified):
  - Layer panel: thumbnails (`LayerItem` caches the result of `LayerThumbnailRenderer`; regenerated only when a property that changes appearance changes, not on move or opacity), drag-and-drop reordering in the list (a blue line shows the insertion point), new (empty image layer), duplicate (`Layer.Clone()`), merge down (`LayerMerger` / `MergeLayersCommand`; both only when the layer is visible). Thin separators between rows (bottom border of the row in `LayerListStyle`). The visibility toggle is an eye icon (`EyeCheckBoxStyle`; still a CheckBox underneath; hidden shows a slash). The list's context menu (contents decided in `ContextMenuOpening`): "画像レイヤーにラスタライズ" (shown only when `LayerRasterizer.CanRasterize`) and "下のレイヤーと結合" (grayed out when merging is impossible). The right-clicked row is selected first. The buttons at the bottom (new, duplicate, merge, move up, move down, delete) are icon-only in a single row (`LayerIconButtonStyle`; glyph in Tag, description in ToolTip; small, 14px).
  - Canvas: Delete removes (disabled while typing text), arrow keys move 1px and Shift+arrow moves 10px (holding a key is one step), handles on the selected shape (`ShapeHandles` / `SetShapeGeometryCommand`), double-click on text to edit in place (`CanvasView.TextEditing.cs`; the layer being edited is excluded from rendering via `CanvasRenderer.Render(exclude:)`, and input is applied immediately as merged commands). Input handling is in `CanvasView.Interaction.cs`.
  - Unsaved-changes prompt: `CommandHistory.IsModified` / `MarkSaved()` (remembers the command at the time of saving; undoing back to it returns to unmodified). The tab name shows "●". A successful project save, image export, or clipboard copy marks the document as unmodified (output counts as "handed off"; plan.md 7.1). A prompt appears when closing a tab or exiting the app (Yes = save / No = discard / Cancel).
  - The right panel has properties (`PropertiesPanel`) on top and layers (`LayerPanel`) below, separated by a `GridSplitter` (initially 280 for the top). When the window height changes, the properties height is kept proportionally (SizeChanged of `SidePanelGrid`, within the properties minimum of 80 and layer list minimum of 150). A vertical `GridSplitter` also sits between the canvas and the right panel (right panel initially 240 wide, 200-600; canvas minimum 200). The height is changed only by the user and does not change with the kind of selection. A hint is shown when there is nothing to display.
  - Status bar: the zoom level at the bottom left (updated from `DocumentTab.Zoom` change notifications). Clicking opens a popup of presets. Zoom handling is centralized in `CanvasView.ZoomTo` (shared by wheel, Ctrl+/-, and the menu). Ctrl+1 = 100%, Ctrl+0 = fit.
  - Adding shapes: the toolbar has a single "図形" button; pressing it opens a popup to choose rectangle, ellipse, or arrow (it closes once chosen).
  - Pen: the toolbar's "ペン" enters drawing mode, and a popup lets the user choose a color (a 30-color palette plus "その他の色…", which opens `ColorPickerDialog`: a saturation × brightness square and a hue bar, with numeric entry for H/S/B, R/G/B, and hex; the color is held in one place and the field being typed in is never overwritten) and a width (1-40px). The drawing target follows Photoshop: if a visible image layer is selected, draw directly on its pixels (`PaintStrokeCommand`; keeps before/after patches only for the touched area, one stroke = one Undo step; pixels are written back with row copies because the layer's bitmap carries the immutable flag). Otherwise (a text or shape layer is selected, etc.), create a new transparent image layer named "ペン" (`LayerFactory.CreateStrokeImage`), draw on it, and keep drawing there afterward. Anything outside the image layer's bounds is clipped. Right after startup the screenshot layer is selected, so drawing as-is draws on the original image (Undo is available). Leave the mode with Esc, "ペンをやめる" in the popup, or by adding text or a shape. The cursor is a pen while in the mode (`PenCursor`). `CanvasView.Pen.cs` / `MainWindow.Pen.cs`.
  - Text bold and italic (`TextLayer.IsBold/IsItalic`; `TypefaceCache` caches per typeface style; also applied to the TextBox used for in-place editing). Shape stroke style (`ShapeDash`: solid, dashed, dotted; an arrow applies it to the shaft only) and rectangle corner radius (`ShapeLayer.CornerRadius`; the radius is limited to half the shorter side). `.trimx` gained `bold` / `italic` / `dash` / `cornerRadius` (older files read with defaults; the version stays 1). Image resize also scales the corner radius.
  - Text shadow (toggled by the HasShadow checkbox; the values are kept even when OFF. ShadowOpacity (0-1) and ShadowBlur (blur radius) are sliders; ShadowOffsetX/Y are numeric. Black. It is drawn opaque off-screen and then blurred and faded, so the outline is shadowed too and overlapping parts do not get darker. The bounds include the blur. Older files treat shadowOpacity>0 as ON) and outline (OutlineWidth / OutlineColor; appears only outside the glyphs). Draw order is shadow, then outline, then text. The bounds (GetBounds) include the outline and shadow. Added a "line" shape (ShapeKind.Line; like an arrow it has 2 handles for start and end; shared with arrows through ShapeKind.IsSegment(); solid, dashed, and dotted allowed). `.trimx` gained text shadow / outline fields (older files read with defaults).
  - Rectangular selection, crop, copy, cut: the toolbar's "範囲選択" enters selection mode (mutually exclusive with the pen; `CanvasView.Selection.cs`). Drag to create a rectangle, reshape with 8 handles, drag inside to move, and clear with a click (hardly any movement) or Esc. The selection is `DocumentTab.Selection` (document pixels; not in the history; cleared when the canvas size changes). The area outside is dimmed, and the border is a white solid line plus a black dashed line.
    - Crop: `CropCanvasCommand.Create`. Resizes the canvas to the selection, trims image layers to the selection (pixels outside are discarded; a layer that does not overlap at all stays as a 1×1 transparent layer that keeps only its name and order), and shifts text and shapes by position only, keeping them editable. The history keeps the original bitmaps for Undo (a combination of `ReplaceLayerCommand` / `SetLayerPositionCommand`). The selected layer is re-selected at the same stack position. The zoom level is not changed (`DocumentTab.KeepZoomOnSizeChange`; set only during crop, Undo, and Redo, and `CanvasView` then corrects only the scroll position instead of re-fitting. Canvas resize and image resize still re-fit as before).
    - Copy (Ctrl+C): with no selection, copies the whole composite as before. With a selection, copies only the pixels inside the selection for the selected layer (the composite's range if no layer is selected). Text and shapes are rendered and copied too (`ExportRenderer.RenderLayerRegion` / `RenderRegion`). A partial copy does not count as "saved".
    - Cut (Ctrl+X): applies only to a selected, visible image layer. Writes to the clipboard, then makes the region transparent with `ClearRegionCommand` (keeps before/after only for the touched area). Not available for text or shapes (rasterize first).
  - My colors: colors confirmed with OK in the color picker are recorded automatically, newest first, up to 4, in `MyColors` of `TrimxState.json` (`MyColorService`; a duplicate color moves to the front). It is an app-wide palette. The "…" button on `ColorField` (the text, outline, and shape color fields) opens the same `ColorPickerDialog`, and the chosen color goes into my colors (the pen popup reloads them every time it opens). ColorField itself does not show a my-colors box yet.
  - Toolbar: icon-only buttons (Segoe Fluent Icons; `ToolBarButtonStyle`; glyph in Tag; Content is not rendered but kept as the UI Automation name; the description is the ToolTip; the ToolTip is shown even when disabled). Three groups: left = file (new, open, save, export); center = pen, shape, text | cut, select, crop | canvas, image size | fit | undo, redo; right = paste, copy. Undo and redo are `ApplicationCommands.Undo/Redo` (Ctrl+Z / Ctrl+Y). Characters missing from the icon font (such as Unicode geometric symbols) render as the same box, so do not use them.
  - Settings (the gear at the right end of the toolbar opens `SettingsDialog`; changes apply immediately and are saved to `TrimxSetting.json`; there is no OK / Cancel): theme (system / dark / light; `AppSettings.Theme` is stored as a string so a typo from hand-editing cannot make the whole file unreadable), toolbar label display ON/OFF (`AppSettings.ShowToolbarLabels`; XAML binds `UiOptions.Instance` directly), copyright display ("© 2026 shin32t"), and "reset drawing settings to defaults". `ThemeService` swaps the brushes (`*Brush`) in Application.Resources for the theme, so **always reference color brushes with `DynamicResource`** (they do not switch with `StaticResource`); from code, use `SetResourceReference`. The canvas background is `ThemeService.CanvasBackground` (redraws on the `Changed` event). "System" follows Windows at startup and when the Windows setting changes (`SystemEvents.UserPreferenceChanged`). Read and write settings as "reload, modify, save" (`SettingsService`) so other fields (such as my colors) are not overwritten.
  - There are two data files (`%LOCALAPPDATA%\Trimx\`). **`TrimxSetting.json`** (`SettingsService` / `AppSettings`) = what the user chooses in the settings dialog (theme, label display). **`TrimxState.json`** (`StateService` / `AppState`) = what the app remembers on its own (last new-image size, my colors, pen color and width, last appearance of text and shapes). State lives in memory as a single instance (`StateService.Current`); after changing it call `MarkChanged()` (saved after a 0.6 s delay; `Flush()` also runs on exit). The initial string for new text comes from a setting (`AppSettings.DefaultTextLabel`; default "テキスト"; falls back to the default when empty) and is not part of the remembered state. Shapes also remember a width and height per kind (`ShapeStyle.Sizes`; rounded so they never exceed the canvas, and centered). The right panel width (`SidePanelWidth`) and the inspector height (`InspectorHeight`) are also saved in `TrimxState.json`, recorded on the splitter's `DragCompleted`, and restored at startup. Carry-over: each time text or a shape is edited in the properties panel, `StateService.Capture` records the appearance (excluding position, size, and content), and it is applied the next time one is added through the `applyStyle` of `LayerFactory.CreateText/CreateShape` (`StateService.ApplyText/ApplyShape`). Items with nothing remembered use the previous defaults (such as a text size and stroke width scaled to the image size). "Reset to defaults" is `StateService.ResetDrawingStyles` (clears only the remembered pen, text, and shape styles; my colors and the image-size history stay). The old `settings.json` is read once and migrated into both files; the file itself is not deleted (`LegacySettingsFile`).
- Phase 4 implemented (interactions not verified on a real screen): project save and load, image export, copy to the clipboard, opening files (drag and drop supported).
  - `Trimx.Core.Services` (WPF-independent): `ProjectFileService` (`.trimx` = ZIP; `project.json` + one PNG per layer; format details in plan.md 6.3), `ImageExportService` (PNG / JPEG / WebP; JPEG is flattened onto white, WebP is lossless), `ImageImportService` (PNG / JPEG / WebP / BMP; the header dimensions are checked first), `AtomicFile` (replace via a temporary file). Rendering is done by `ExportRenderer`.
  - Loading treats input as untrusted: the dimension limit is `ImageLimits.MaxSide`; ZIP entries are read in memory by looking up only the names in the manifest (never extracted to disk), and limited by declared size and actual bytes read.
  - UI: `MainWindow.Files.cs` (open, save, export, copy, drop). Ctrl+O / Ctrl+S / Ctrl+Shift+S / Ctrl+E / Ctrl+C. Saving, loading, and exporting are synchronous (wait cursor).
  - Ctrl+C puts the whole edited result (keeping transparency) on the clipboard as an image and in "PNG" format. How it should interact with copying the selected layer is undecided, as noted in plan.md 7.2.
  - Not implemented: BMP export (marked "under consideration" in plan.md).
- Not implemented: single instance and optimization (Phase 5).
- Manual verification on a real screen is partial (build, startup, Core behavior, button operations, confirmation dialogs; mouse and key operations are not verified).
- Tips for automated screen checks: launch the app as `dotnet <temp folder>\Debug\net10.0-windows10.0.19041.0\Trimx.dll`, not as an exe (an exe in a temp folder is refused execution). Button operations can use UI Automation's InvokePattern, and the screen can be captured with PrintWindow (call `SetProcessDPIAware` first for DPI correctness). In this environment synthetic mouse and key input does not reach the app, so verify dragging, double-clicking, and key operations on a real machine.
